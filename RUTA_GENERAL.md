# Ruta general de aprendizaje de Python

Esta ruta organiza el repositorio en una base común y varias líneas de aplicación. Está diseñada para avanzar mediante ejercicios pequeños y proyectos acumulativos, sin obligar a instalar todas las bibliotecas ni a recorrer todas las áreas.

## Cómo se organiza

- **Sesiones 1–12 — Fundamentos:** sintaxis, tipos, entrada/salida, operadores, condicionales, ciclos, colecciones, funciones, archivos, excepciones y un cuestionario integrador.
- **Nivel 2 — Programas mejor estructurados:** módulos, rutas, depuración, pruebas, entornos virtuales, paquetes y Git.
- **Rutas de aplicación:** interfaces gráficas, juegos, automatización, datos y gráficas, imágenes, web y APIs, ciencia, IA introductoria y comunicación con dispositivos.
- **Proyectos integradores:** programas pequeños que combinan varias competencias y dejan una evidencia verificable.

## Secuencia recomendada

| Etapa | Aprenderás | Producto orientativo |
|---|---|---|
| A. Fundamentos | Sintaxis, tipos, entrada/salida y operadores | Ficha de presentación y calculadora |
| B. Lógica | Condicionales, ciclos y validación | Juego de adivinanza |
| C. Estructuras | Cadenas, listas, diccionarios y conjuntos | Gestor sencillo de datos |
| D. Organización | Funciones, módulos, excepciones y archivos | Cuestionario que guarda resultados |
| E. Herramientas | Entorno virtual, instalación de paquetes, depuración y pruebas | Proyecto organizado y documentado |
| F. Primer contacto visual | Turtle y Tkinter | Dibujo interactivo y formulario |
| G. Interfaces modernas | CustomTkinter, eventos y persistencia | Aplicación de escritorio |
| H. Juegos | Pygame, eventos, movimiento y colisiones | Juego 2D pequeño |
| I. Datos y automatización | CSV, JSON, pathlib, estadísticas y gráficas | Informe automático con visualización |
| J. Web y APIs | HTTP, JSON, Flask o FastAPI | API o pequeña aplicación web |
| K. Exploración | Pillow, NumPy, IA introductoria o pyserial | Proyecto elegido según un problema real |

El orden es orientativo. Después de la etapa D puedes elegir una ruta según el interés y los recursos disponibles. Los módulos de aplicación deben repasar los conceptos necesarios sin asumir que el estudiante los recuerda perfectamente.

## Reglas para diseñar cada módulo

1. Declarar el objetivo y los conocimientos previos.
2. Indicar qué se necesita instalar y cómo comprobar la instalación.
3. Mostrar un ejemplo completo y pequeño.
4. Explicar el código por partes, no solo entregarlo.
5. Proponer experimentos donde el estudiante prediga el resultado antes de ejecutar.
6. Incluir retos básico, intermedio y de ampliación.
7. Documentar errores frecuentes y formas de diagnosticarlos.
8. Definir qué evidencia demuestra que el proyecto funciona.
9. Separar las mejoras opcionales de los requisitos mínimos.
10. Enlazar documentación oficial y señalar cualquier limitación conocida.

## Criterios para elegir herramientas

- Empezar con la biblioteca estándar siempre que sea suficiente.
- Instalar una dependencia externa solo cuando el proyecto la necesite.
- Preferir ejemplos que funcionen sin cuentas, servicios de pago o claves secretas.
- Mantener una alternativa sencilla para computadores modestos.
- No confundir que el código compile con que la interfaz, el juego o el hardware se hayan probado en la práctica.
- Mantener cada proyecto separado, con su propio README y dependencias cuando crezca.

## Estado de implementación

Las sesiones 1–12 forman la base existente. Las rutas aplicadas se incorporarán por fases, comenzando por interfaces y juegos. La documentación de una ruta es una guía de trabajo; cada proyecto deberá implementarse y verificarse antes de marcarse como terminado.

Consulta el [catálogo de rutas](rutas/README.md) para elegir un área.
